并发安全状态：最小速查表

适用于共享计数器、内存 KV、任务表和请求去重表。先决定状态由谁拥有，再让每一次读写遵守同一套同步规则。

判断数据竞争

两个或更多 goroutine 并发访问同一变量，且其中至少一个是写，并且没有适当同步，就是 data race。

  • 写 + 写：两个请求同时更新同一个计数器或 map。
  • 读 + 写：一个请求读取值，另一个请求同时更新它。
  • 读 + 读：通常不是 data race；仍要考虑数据结构自身的约束。

Mutex 模板

type Counter struct {
	mu   sync.Mutex
	hits int
}

func (c *Counter) Add() {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.hits++
}

func (c *Counter) Value() int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.hits
}

mu 保护 hits。只要有并发写入，所有对 hits 的并发读和写都必须遵守这一约定。defer 让函数返回时释放锁，避免以后加入分支时漏掉 Unlock。

验证命令

go test 的用途：编译并运行当前 Go module 中以 _test.go 结尾的测试文件。请在含有 go.mod 的项目根目录运行它。

./... 的含义：从当前目录 . 开始，递归选择所有子 package；练习只有一个 package 时也可写 .。

-race 的含义：启用 Go 内置的数据竞争检测器。命令成功时通常输出 ok <package>；发现问题时会显示 WARNING: DATA RACE 和冲突访问的调用栈。

go test ./...
go test -race ./...

-race 只会发现实际运行到的路径上的竞争；绿色结果不是并发正确性的数学证明。用测试制造并发访问，并人工检查状态所有权。

调试顺序

  1. 从 race report 找到冲突的读/写位置和 goroutine 创建位置。
  2. 写出“哪个锁（或哪个 goroutine）拥有这份状态”。
  3. 让每个访问点遵守同一个同步规则，再运行 go test -race。
  4. 最后确认锁粒度没有把网络 I/O 或缓慢操作包在临界区里。
