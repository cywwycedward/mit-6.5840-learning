学习工作区 Git：最小速查表

目标不是积累复杂流程，而是让每个学习里程碑可说明、可验证、可恢复。

只记住这条主线

main（稳定、可复习） └─► topic branch（一个目标） └─► 验证 + 原子提交 └─► 自审 + fast-forward 合并回 main

跟踪判断

  • 提交：课程、学习记录、参考资料、代码、测试、`go.mod`/`go.sum`、`.scratch/` 问题记录和项目共享配置。
  • 忽略：二进制、覆盖率、日志、临时文件、本机 IDE 状态和任何密钥。
  • 先确认：第三方资料的许可、agent 配置是否共享、以及任何可能包含凭据的文件。

分支与提交

lesson/<topic>     exercise/<topic>     docs/<topic>
ref/<topic>        fix/<topic>          chore/<topic>

<type>(<scope>): <简短的动作说明>
feat(counter): 支持并发读取
docs(workflow): 定义 Git 管理规范

一个提交一个理由。实现与证明它正确的测试可以同行；无关格式化、资料搬运和功能调整必须拆开。

提交前四问

  1. 暂存区是否只有这一目标的文件？
  2. diff 是否没有密钥、构建产物、无关改动或实验解答？
  3. 文档链接、测试及 race 检测是否已按改动类型运行？
  4. 提交标题是否能说明“为什么存在这次变化”？

保护边界。main 不 force-push；共享提交不改写历史。遇到不认识的改动先检查，不用 reset --hard 或 clean -fd 清掉它。

完整规范：Git 管理规范；工作区约定摘要见 AGENTS.md。权威资料：Pro Git（官方）、gitignore 文档。
