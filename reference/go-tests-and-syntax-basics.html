读懂第一份 Go 测试代码

这不是“记住模板”。目标是知道 Go 测试如何被发现、函数签名中每一段处于什么位置，以及循环到底会运行多少次。

1. testing 包：谁运行测试？

testing 是 Go 标准库，用来描述测试的失败、日志和测试上下文。你不需要自己创建 testing.T，也不需要在代码中手动调用测试函数；go test 会生成测试程序并调用符合约定的函数。

// 文件名必须以 _test.go 结尾
package counter

import "testing"

// 函数名以 Test 开头，参数固定为 *testing.T。
func TestCounterConcurrentAdd(t *testing.T) {
	// 断言代码写在这里
}
  • counter_test.go：后缀 _test.go 让 go test 在测试时包含它，而普通构建不包含它。
  • package counter：测试与被测代码处在同一 package，因此可以直接使用 Counter。
  • import "testing"：允许写出 testing.T 这个类型。
  • TestCounterConcurrentAdd：Test 前缀使它成为测试入口；剩余名字说明正在验证什么。
  • t *testing.T：t 是变量名，*testing.T 是类型。星号表示指向测试上下文的指针；现在只需把它理解为“测试运行器传进来的报告工具”。

如何报告失败

t.Errorf("hits = %d, want %d", got, want) // 记录失败，但当前测试继续执行
t.Fatalf("hits = %d, want %d", got, want) // 记录失败，并立刻结束当前测试函数

f 表示 format（格式化）：字符串里的每个 %d 会依次被后面的整数替换。第三节课使用 Fatalf，因为数量不对时继续执行没有意义。

2. 为什么有的括号在函数名前？

你看到的是两种不同声明：普通函数和方法。普通参数永远在函数名后面的圆括号中；函数名前的圆括号是方法的 receiver（接收者）。

// 普通函数：名字在前，普通参数在名字后。
func TestCounterConcurrentAdd(t *testing.T) {
	// ...
}

// 方法：receiver 在名字前，普通参数仍在名字后。
func (c *Counter) Add() {
	c.hits++
}

// 也可以有返回值；返回类型放在参数列表后。
func (c *Counter) Value() int {
	return c.hits
}
  • (c *Counter) 不是 Add 的普通参数；它声明 Add 属于 Counter。因此能写 c.Add()。
  • c 是接收者变量名；*Counter 是它的类型。* 表明方法操作同一个 Counter 实例，而不是获得它的一份拷贝。
  • t *testing.T 和 c *Counter 都遵循 Go 的“名字在前，类型在后”规则。只有 receiver 的位置特殊：它额外放在方法名之前。
  • int 在 Value() int 的最后，是返回类型，不是参数。

3. for range workers 到底做什么？

const workers = 3

for range workers {
	// 这里恰好运行 3 次
}

这在 Go 1.22 起合法。若右侧是整数 n，循环产生从 0 到 n-1 的值；本例不需要那个索引，所以没有给它起名字。也就是说，for range workers 的效果是“重复 worker 数量次”。你的 Go 1.26.5 和 6.5840 要求的 Go 1.22+ 都支持它。

// 当索引本身也有用时，写出它：
for i := range workers {
	// i 依次为 0、1、2
}

// 更传统、在旧版 Go 也可用的等价写法：
for i := 0; i < workers; i++ {
	// i 依次为 0、1、2
}

第一种写法中的 := 表示“声明并赋值”；i 的作用域是整个循环块。第三节课中的内层 for range addsPerWorker 同理：它让每一个 worker 恰好调用 Add 100 次。

4. 把测试主体逐行翻译

var c Counter                 // 新建被测计数器，初始 hits 为 0
var wg sync.WaitGroup         // 新建等待计数器
wg.Add(workers)               // 告诉它：有 100 个 goroutine 要等待

for range workers {           // 重复 100 次，启动 100 个 worker
	go func() {                 // 定义匿名函数，并在新的 goroutine 中调用它
		defer wg.Done()           // 函数返回前把等待计数减 1
		for range addsPerWorker { // 每个 worker 加 100 次
			c.Add()
		}
	}()                          // () 是“现在调用这个匿名函数”
}
wg.Wait()                     // 阻塞到所有 worker 都调用 Done 为止

if got, want := c.Value(), workers*addsPerWorker; got != want {
	t.Fatalf("hits = %d, want %d", got, want)
}

最后的 if 有两部分：分号前用 := 声明 got 和 want；分号后比较它们。它们只在这个 if 语句及其花括号内可见。got 是实际值，want 是期望值。

容易混淆的点：go func() { ... } 只是形成匿名函数，尚未调用；末尾 () 才是调用。完整的 go func() { ... }() 才会让这次调用在新 goroutine 中独立执行。
