与后端的连接。HTTP/RPC server 通常会并发处理请求。若所有请求都修改同一份内存状态（计数器、map、任务表），正确性不再来自“代码按顺序执行”，而来自明确的同步规则。MIT 的 MapReduce Lab 1 也明确提醒：coordinator 的 RPC server 是并发的，必须保护共享状态。

先预测，不查答案

下面的 hits++ 看起来像一个动作，但它会读取旧值、计算新值、写回新值。两个 goroutine 同时执行它时，可能都读取到相同旧值，导致一次更新被覆盖。

type Counter struct {
	hits int
}

func (c *Counter) Add() {
	c.hits++ // 多个 goroutine 同时调用 Add 时有问题
}

检查 1

两个 goroutine 同时调用 Add，它们都写 hits，且没有同步。这是 data race 吗？

建立一个可说清楚的规则

这节课使用最直接的规则：Counter.mu 拥有并保护 Counter.hits。每次读取或修改 hits 前先获取同一把锁；结束后释放它。

请求 A ─┐ ├─► Lock ─► 修改 hits ─► Unlock 请求 B ─┘ ▲ └── B 必须等待；因此不会与 A 同时读写 hits
package counter

import "sync"

type Counter struct {
	mu   sync.Mutex
	hits int
}

func (c *Counter) Add() {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.hits++
}

func (c *Counter) Value() int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.hits
}

defer c.mu.Unlock() 的意思是：无论函数在哪个返回点结束，离开函数前都执行 Unlock。这里它降低了以后修改函数时忘记解锁的风险。

检查 2

既然 Add 已加锁，为什么 Value 也必须使用同一把锁？

A：因为读操作会自动串行。　B：因为读操作可能与写操作同时发生。

亲手验证：让测试制造并发

命令卡：创建练习项目

go mod init <模块路径> 的作用是：在当前目录创建 go.mod，把该目录声明为一个 Go module（Go 用它记录项目身份和依赖）。只需在每个新项目的根目录执行一次。

在你新建的空目录 safe-counter/ 中运行 go mod init example.com/safe-counter。这里 example.com/safe-counter 是这个练习的模块路径；它不需要是真实网站。成功后应看到 go: creating new go.mod，并在当前目录得到 go.mod 文件。

接着创建 counter.go（上一节的 Counter 实现）和下面的 counter_test.go。两个文件必须位于同一目录，且都使用 package counter。

// counter_test.go
package counter

import (
	"sync"
	"testing"
)

func TestCounterConcurrentAdd(t *testing.T) {
	const workers = 100
	const addsPerWorker = 100

	var c Counter
	var wg sync.WaitGroup
	wg.Add(workers)

	for range workers {
		go func() {
			defer wg.Done()
			for range addsPerWorker {
				c.Add()
			}
		}()
	}
	wg.Wait()

	if got, want := c.Value(), workers*addsPerWorker; got != want {
		t.Fatalf("hits = %d, want %d", got, want)
	}
}

命令卡：运行带竞争检测的测试

go test 会编译并运行当前 module 中所有以 _test.go 结尾的测试。-race 会额外启用 Go 的 data race detector；./... 表示当前目录及所有子目录的 package。请仍在含有 go.mod 的 safe-counter/ 根目录运行。

完整命令是 go test -race ./...。修复后，预期看到 ok；未加锁时，预期看到 WARNING: DATA RACE。这是诊断证据，不是“偶尔失败就重跑”的提示。

检查 3

go test -race 通过后，能否证明程序所有路径都没有 data race？

为何这比“先学 Raft”更重要？

Raft 的一个 peer 同时处理选举计时器、RPC 回复、日志复制和客户端提交；其中的共享状态比 hits 多得多。若现在无法明确“哪个锁保护哪项状态”，Raft 中的错误会难以定位。先把这个小规则练到能解释，才有能力处理后面的复杂状态机。
