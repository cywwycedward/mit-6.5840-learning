0. 先建立问题：一次 hits++ 不是原子的

HTTP 或 RPC server 会并发处理请求。若多个请求修改同一份内存状态，例如计数器、map 或任务表，正确性不再来自“代码按顺序执行”，而来自明确的同步规则。

hits++ 是把整型变量加一的语句，不能作为另一个表达式的一部分；它看起来像一个动作，实际至少包含：读取旧值、计算新值、写回新值。两个 goroutine 交错执行时，可能都读取同一个旧值，令其中一次更新被覆盖。这种未同步的并发访问称为 data race（数据竞争）：多个 goroutine 并发访问同一内存位置，至少一个是写，且没有同步。

1. 读懂第一个 Go 类型和方法

语法卡：package、import 与选择器

每个 Go 源文件第一条非注释声明通常是 package counter。package 表示本文件属于名为 counter 的 package；同一目录中准备一起编译的普通 Go 文件应使用同一个 package 名。

import "sync" 把标准库的 sync package 引入当前文件。导入后写 sync.Mutex：点号左边是 package 名，右边是其中导出的名称。这种“名称空间.名称”的写法叫 selector（选择器）。

语法卡：结构体、字段、方法与指针接收者

type Counter struct { hits int } 声明一个新类型：Counter 是类型名，struct 表示它由字段组成，花括号内的 hits int 表示字段名在前、类型名在后。

func (c *Counter) Add() 声明方法。func 开始函数声明；(c *Counter) 位于方法名 Add 之前，叫 receiver（接收者），让我们能写 c.Add()。其中 c 是方法体内的变量名，*Counter 是“指向 Counter 的指针”，所以方法能修改调用者原来的那一份状态，而不是副本。

这与普通参数的位置不同：普通函数写成 func add(x int, y int) int。函数名后的小括号装参数；每个参数都是“名字在前、类型在后”；末尾的 int 是返回值类型。没有返回值时，末尾类型省略。

package counter

type Counter struct {
	hits int
}

func (c *Counter) Add() {
	c.hits++ // 这里暂时还不安全
}

两个 goroutine 同时调用上面的 Add，都写 hits，且没有同步。这是 data race 吗？

2. 用 Mutex 给共享状态建立规则

API 卡：sync.Mutex、Lock、Unlock 与 defer

sync.Mutex 是互斥锁。把它看作一扇门：Lock() 获取门锁；若已有别的 goroutine 持有锁，当前 goroutine 会等待。Unlock() 释放锁，让等待者之一能够继续。锁不是数据本身；它是一个约定：Counter.mu 保护 Counter.hits，因此每次读或写 hits 都必须先获取同一把锁。

defer c.mu.Unlock() 的语法是关键字 defer 加一个函数调用。它不会立刻调用 Unlock，而是登记为“当前函数返回前执行”。return expression 结束当前函数并把 expression 交给调用者；在真正返回前，本函数已登记的 defer 会执行。因此即使函数后来增加了多个 return，也较不容易漏掉解锁。defer 只影响当前 goroutine 的当前函数调用。

请求 A ─┐ ├─► Lock ─► 修改 hits ─► Unlock 请求 B ─┘ ▲ └── B 必须等待；不会与 A 同时读写 hits
package counter

import "sync"

type Counter struct {
	mu   sync.Mutex
	hits int
}

func (c *Counter) Add() {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.hits++
}

func (c *Counter) Value() int {
	c.mu.Lock()
	defer c.mu.Unlock()
	return c.hits
}

return c.hits 结束 Value 并把 hits 的值交给调用者；执行返回前，已经登记的 defer c.mu.Unlock() 会先运行。读操作也要锁，因为“一个 goroutine 读、另一个 goroutine 写”同样是 data race。

3. 完整理解循环与 range

Go 没有独立的 while 或 do...while；所有重复执行都由 for 表达。range 不是独立语句，而是 for 的一种子句。读 for x := range y 时，固定问四件事：y 的类型是什么？每轮得到什么？顺序保证吗？何时停止？

3.1 四种常用 for 形式

形式语法中每一部分的意思行为
for condition { ... }condition 是布尔表达式。每轮开始前求值；为真才运行循环体。相当于许多语言的 while。
for init; condition; post { ... }init 只执行一次；三段由分号隔开；post 在每轮末尾执行。常用于带计数器的循环。
for range x { ... }x 是被遍历的 range expression。不需要迭代值时使用；本节的 worker 循环属于此类。
for { ... }没有条件。无限循环；必须在内部有 break、return、阻塞或其他可说明的退出路径。

:= 是短变量声明：在当前作用域创建至少一个新变量，并从右侧推导类型；retries := 0 创建类型为 int 的变量。i++ 将 i 加一；循环体的花括号形成一个块作用域。

retries := 0
for retries < 3 {
	retries++
}

for i := 0; i < 3; i++ {
	// i 依次为 0、1、2
}

i++ 是语句，不能嵌在别的表达式里。条件为假时循环体一次也不执行；三段式循环的 init 只运行一次，而 post 在每轮末尾运行。

3.2 range 左侧：声明、赋值与丢弃值

for range x { }          // 不需要迭代值
for v := range x { }     // 声明一个迭代变量
for a, b := range x { }  // 声明两个迭代变量
for a, b = range x { }   // 给已经存在的变量赋值
for _, v := range x { }  // 丢弃第一个值

:= 声明变量，= 只赋值、不会新建变量。_ 是空标识符，表示“这个值刻意不使用”。右侧表达式会在开始遍历前求值一次。channel 和整数至多提供一个值；array、slice、string、map 通常可提供两个值。

3.3 不同右侧类型的精确行为

右侧类型可得到的值顺序与停止必须记住
array / slice第一个是索引；第二个是元素值的副本。索引从 0 递增到 len(x)-1；nil slice 为零轮。要改原 slice 用索引：for i := range xs { xs[i]++ }。for _, v := range xs { v++ } 只改副本。
string第一个是 UTF-8 byte 偏移；第二个是 Unicode code point（rune）。从左到右解码；无效 UTF-8 产生 U+FFFD 并前进一个 byte。字符串不是按“一个字符一个 byte”遍历。
map第一个是 key；第二个是 value 副本。遍历顺序未指定，不能依赖两次相同。不同 goroutine 未同步读写同一 map 仍是 data race；range 不能替代 Mutex。
channel每轮收到一个元素。没有值时等待；关闭且已接收完缓冲值后停止；nil channel 永远阻塞。for task := range tasks 的结束信号是关闭 channel，不是特殊任务值。
整数（Go 1.22+）一个索引值：0 到 n-1。n <= 0 时零轮。for range workers 只重复 workers 次；for i := range workers 同时取得索引。

本课程的代码使用最后一行的整数 range。MIT 6.5840 的最低 Go 版本是 1.22，因此它可用。Go 1.22+ 中，用 := 声明的循环变量每一轮是独立变量；这减少了闭包捕获旧循环变量的错误，但绝不让共享 map、slice 或 struct 自动变得并发安全。

map[string]int{...} 是 map 字面量：string 是 key 类型，int 是 value 类型；花括号列出初始 key/value。for task := range tasks 的 tasks 必须是 channel，handle(task) 是一次普通函数调用。这两种形式在后续课程会用于任务表和 worker。

status := map[string]int{"pending": 2, "done": 5}
for key, value := range status {
	// 不要假设 pending 一定先于 done
}

for task := range tasks {
	handle(task) // 发送方关闭 tasks 后，循环自然结束
}

3.4 break、continue 与标签

break 立即退出最近一层 for；continue 跳过本轮余下语句并开始下一轮。三段式循环中的 continue 仍会执行轮尾的 post。if condition { ... } 先判断布尔条件，真时执行块。需要影响外层嵌套循环时，把标签紧贴在目标循环前：

Outer:
for _, batch := range batches {
	for _, task := range batch {
		if task.Cancelled {
			continue Outer // 直接开始下一个 batch
		}
		if task.Fatal {
			break Outer // 同时退出两个循环
		}
	}
}

没有标签的 break 和 continue 只影响最内层循环；业务代码优先通过拆分函数保持清晰，标签只在它最直接时使用。

4. 写测试前，认识 testing、goroutine 与 WaitGroup

命令卡：go mod init <模块路径>

作用：在当前目录创建 go.mod，把该目录声明为一个 Go module；Go 用它记录项目身份和依赖。在哪里运行：新建练习项目的根目录，例如 safe-counter/，每个项目只需一次。参数：go 是工具；mod 是模块子命令；init 是初始化动作；example.com/safe-counter 是模块路径，不需要是真实网站。

执行 go mod init example.com/safe-counter 后，预期出现创建 go.mod 的提示。确认方式是查看当前目录中是否已有该文件；不要在上级课程目录反复运行它，否则会把多个练习混成一个 module。

语法卡：测试文件、testing.T 与失败报告

testing 是 Go 标准库。go test 自动查找文件名以 _test.go 结尾、函数形如 func TestXxx(t *testing.T) 的测试；你既不手动调用测试函数，也不自己创建 t。

t 是变量名，*testing.T 是类型；它是测试运行器交给测试函数的报告工具。t.Fatalf(format, values...) 记录失败并立刻结束当前测试函数。其中 %d 是格式占位符，会由之后的整数替换。

语法卡：常量、零值、匿名函数与 go

const workers = 100 声明不能重新赋值的常量。var c Counter 声明一个明确类型的变量；未显式赋值时，字段取类型的零值，int 的零值为 0。var wg sync.WaitGroup 也能直接使用，因为 WaitGroup 的零值代表“没有尚未完成的任务”。

func() { ... } 是没有名称、没有参数的匿名函数；末尾的 () 是立即调用它。最前面的 go 把这次函数调用放入新的 goroutine 并发执行：go func() { ... }()。若漏掉最后的 ()，只是定义了函数值，既没有调用，也没有启动 goroutine。

5. WaitGroup：等待任务结束，不保护数据

sync.WaitGroup 是“未完成任务”的计数器，而不是 Mutex 的替代品。它回答“所有 worker 都结束了吗？”；Counter.mu 回答“现在能否安全读写 hits？”

初始：0 Add(3) ─► 3 登记三个任务 Done() ─► 2 第一个任务结束 Done() ─► 1 第二个任务结束 Done() ─► 0 第三个任务结束；Wait 解除阻塞
方法用途本例中的时机
wg.Add(n)计数增加 n。在启动 n 个 goroutine 前登记任务。
wg.Done()计数减一，等价于 wg.Add(-1)。每个 worker 返回时执行一次。
wg.Wait()当前 goroutine 阻塞，直到计数为零。启动 worker 后、读取最终结果前。

必须遵守三条规则：第一，正数 Add 要在启动 goroutine 前完成，否则 Wait 可能先看到 0 并提前返回；第二，每个 Add(1) 必须恰好有一次 Done()，少一次会永久等待，多一次会因负计数而 panic；第三，首次使用后不能复制 WaitGroup，传入函数时使用 *sync.WaitGroup。

Go 1.25 添加了 wg.Go(f)，能启动函数并自动配平计数；但 MIT 6.5840 最低要求是 Go 1.22，因此本课程使用兼容的 Add 加 defer Done 模式。传给 wg.Go 的函数不能 panic。

6. 把这些规则组合成并发测试

语法卡：带初始化语句的 if

if got, want := actual, expected; got != want { ... } 有两部分：分号前的 got, want := actual, expected 创建实际值和期望值，它们的作用域只覆盖这个 if；分号后的 got != want 是条件。!= 表示“不相等”，* 是整数乘法。这样写能让失败消息同时使用 got 和 want，又不把它们暴露到后续代码。

创建 counter.go（上文第 2 部分的 Counter 实现）和下方的 counter_test.go，两个文件位于同一目录并声明 package counter。

// counter_test.go
package counter

import (
	"sync"
	"testing"
)

func TestCounterConcurrentAdd(t *testing.T) {
	const workers = 100
	const addsPerWorker = 100

	var c Counter
	var wg sync.WaitGroup
	wg.Add(workers)

	for range workers {
		go func() {
			defer wg.Done()
			for range addsPerWorker {
				c.Add()
			}
		}()
	}
	wg.Wait()

	if got, want := c.Value(), workers*addsPerWorker; got != want {
		t.Fatalf("hits = %d, want %d", got, want)
	}
}
逐行说明这段测试的关键控制流

wg.Add(workers) 在主 goroutine 中先登记全部 worker。外层 for range workers 启动 100 个 goroutine；每个匿名函数一进入就登记 defer wg.Done()，内层整数 range 各做 100 次 c.Add()。

主 goroutine 继续到 wg.Wait() 并等待。所有 worker 都调用 Done 后，Wait 才返回，所以随后读取 c.Value() 时，加法已结束。最后的 if 用前面语法卡所说的局部 got / want 比较实际计数和期望计数；不相等时，Fatalf 立即令该测试失败。

命令卡：go test -race ./...

作用：go test 编译并运行测试；-race 额外启用 data race detector；./... 是 package 模式，表示当前目录与所有子目录中的 package。在哪里运行：仍在包含 go.mod 的 safe-counter/ 根目录。成功结果：修复后会看到 ok；暂时删除 Mutex 后，预期可看到 WARNING: DATA RACE。

验证边界：race detector 是动态工具，只能发现测试实际执行路径中的竞争；通过测试不等于证明程序所有路径都没有竞争。Windows 原生环境下，-race 需要 cgo 和可用的 C 编译器；MIT 课程在 Windows 推荐 WSL2。若再次遇到 cgo 报错，先停止，不要绕过 -race，把完整错误发给我一起确认环境。
