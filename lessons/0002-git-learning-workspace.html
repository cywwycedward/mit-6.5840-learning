先建立正确心智模型。Git 的提交不是“保存按钮”，而是一份有目的、可追溯的快照。工作区是你正在编辑的文件；暂存区是你挑选出来准备成为下一份快照的文件；提交把暂存区永久记录到本地仓库历史。

这个工作区采用的规则

这里只有一个长期分支 main，表示可复习、可运行的学习里程碑。每项实际改动在短生命周期分支中完成，例如 lesson/git-workflow 或 exercise/safe-counter；验证并自审后，以 fast-forward 合并回 main。

main ───●──────────●─── 稳定快照 \ / lesson/git-workflow 一个聚焦目标

完整的跟踪边界、命名和提交规则见 Git 管理规范；提交前可以回看 速查表。

命令卡：首次初始化本地仓库

目的：让当前工作区开始拥有本地历史。请在本项目根目录 MIT6.5840/ 运行命令；不要在 lessons/ 或 src/ 子目录运行。

命令：git init -b main 中，git init 创建 Git 仓库，-b main 把初始分支命名为 main。它只创建本机的 .git/ 元数据，不会联网、上传或修改课程文件。

成功与检查：成功后会显示仓库初始化信息。接着运行 git status --short：status 只读地报告状态，--short 用两列状态简写输出。你应看到当前文件是未跟踪的 ?? 项。

停止/回退：若发现目录选错，先不要执行 add 或 commit；确认后只删除该错误目录下新建的 .git/ 元数据目录即可恢复为未初始化状态。不要删除项目根目录或课程文件。

命令卡：选出第一份快照

目的：把已检查的基线放进暂存区，再创建第一条本地历史。仍在项目根目录运行。

命令：git add --all 中，add 把文件内容放入暂存区，--all 选择所有未被 .gitignore 排除的变化。首次建库时它用于完整基线；日常改动改用 git add <明确路径>，避免误收无关文件。

检查：git diff --cached 只读地显示暂存区将要提交的差异。确认范围正确后，运行 git commit -m "chore(repo): 建立学习工作区基线"：commit 创建本地快照，-m 后的文字是提交标题。成功后再运行 git status --short，预期没有输出。

停止/回退：若暂存区包含错误文件，执行 git restore --staged <路径> 将其移出暂存区；该命令不会删除工作区中的文件。尚未推送的提交需要调整时，先检查差异并向我说明情况，不用猜测性地执行破坏性命令。

命令卡：为下一项学习建立工作分支

目的：把下一项练习和稳定的 main 隔开。确认 git status --short 无输出后，在项目根目录运行 git switch -c exercise/<topic>。switch 切换分支，-c 同时创建分支，<topic> 替换为短小的英文主题，例如 safe-counter。

结果与检查：终端会报告已切换到新分支；git branch --show-current 会只读显示当前分支名。完成并验证后，先运行 git switch main 回到稳定分支，再运行 git merge --ff-only exercise/<topic>。其中 merge 合并分支，--ff-only 只允许无合并提交的直线历史；若不能快进，先停下理解原因。

清理：确认合并成功且 main 可用后，git branch -d exercise/<topic> 删除已经合并的本地工作分支；-d 会拒绝删除尚未合并的分支，因此比强制删除安全。
